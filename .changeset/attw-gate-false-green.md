**The `attw` publish gate exited 0 when the tarball carried no type declarations, so a release that shipped without its `.d.ts` files would have passed every check on the way out.** The gate now refuses that outcome, and it also refuses a build whose declared entry points are not on disk yet.

**The cause is unconditional CLI semantics, not a lenient invocation and not concurrency.** `getExitCode.js` in `@arethetypeswrong/cli@0.18.4` opens with `if (!analysis.types) return 0`, returning before the problem list is read at all, because an untyped package is a legitimate npm package. So "This package does not contain types." is printed as a description rather than a problem. For a package that ships types it means the declarations were not in the tarball, which is a broken publish reported as a pass, and this script is both a CI step and the last step of `prepublishOnly`. Diagnosed first in `@cosyte/terminology`; the code was ported here and every measurement was re-taken on this package.

**Reproduced here with zero concurrency.** On a quiet box, `rm -f dist/index.d.ts dist/index.d.cts && pnpm attw` and `rm -rf dist && pnpm attw` both print the untyped sentence and exit **0**. Concurrency only supplies the condition. `tsup` writes the JS bundles before the declaration files, so every build of this package has a window in which `dist/` holds `index.mjs` and `index.cjs` and no `index.d.ts`: measured over three clean builds on an idle box, polling every 25ms, at **1.06s, 1.23s and 1.43s** (JS at +4.83s to +5.36s, declarations at +6.06s to +6.49s). A concurrent build or `clean` in the same working tree lands the gate in that window. This is why the remedy is not a lock, a lease or a build queue: a lock would leave the defect intact on an idle box, and the gate is supposed to be able to say its own inputs were missing whatever removed them.

**Two nets, which catch different things, and both are kept.** A **preflight** that every relative path `package.json` promises exists and is non-empty, which for this package is `./dist/index.cjs`, `./dist/index.mjs`, `./dist/index.d.ts` and `./dist/index.d.cts`; it catches the build window and names the missing file rather than leaving a reader to infer it from a sentence about types. And a **post-check** promoting the untyped sentence to a failure, which the preflight structurally cannot see: declarations can be present on disk and still be absent from the tarball because `files` or `.npmignore` left them out. No instance of that second case is on record in this repo. **Neither net covers the rest of `files`** (`README.md`, `LICENSE`, `TRADEMARKS.md`, `CHANGELOG.md`), said plainly rather than left to be discovered: `attw` analyses types and never looks at them.

**The post-check reads a string, so the routes that would hide that string are refused, by option and not by value.** Eleven were measured here on a fixture whose tarball genuinely carries no types, each restoring the exact exit 0 with the sentence unreadable: `--quiet`, `-q`, `--format json`, `-f json`, `--format=json`, `-fjson`, `-qf json`, `-Pfjson`, a `.attw.json` setting `quiet` or `format`, and `--config-path` pointing at a file that sets one. That last is the difference from the copy this was ported from, which refused it by inference and said so.

**The three cluster forms are why the predicate is not an exact-token set, and the first draft of this change got that wrong.** It matched each whole argument against a set of exact spellings, and commander lets a short option's value attach to it and lets shorts combine, so `-f` is not visible as a token in `-fjson`. Measured on that draft, on the untyped fixture: `-fjson` gave exit 0 with the gate silent. A single-dash argument is now refused if any character in its cluster is `q` or `f`, which is sound because `-f` is the only value-taking short option this tool has.

Measured in the other direction too, because the bound is what makes the refusal honest: `--format table-flipped` and `--format ascii` still print the sentence and blind nothing, and are refused anyway, since value-parsing them would be a third moving part in the guard; while `--form json`, `--quiet=true` and `-f=json` each look like a route and are not, because the argument parser rejects them outright. Nothing else is refused, so `--profile node16` and `-P` still get through, and a forwarded extra positional does not retarget the run: `--pack .` supplies the first positional and the second is ignored.

**What pins it.** `test/scripts/attw-gate.test.ts` runs both nets against the real binary: the upstream exit 0 itself, so an upgrade that fixes it or rewords the sentence reds instead of letting the net go quietly slack; the build window in this package's own dual ESM/CJS `exports` shape, asserting both that the bare tool passes it with exit 0 and that the wrapper reds naming `./dist/index.d.ts`; a negative control on a well-formed package, because a gate that only ever fails is not a gate; that a real failure still fails with the tool's own exit status; and that other arguments are still forwarded, which is what lets `typecheck:exports` keep its `--profile node16`. **Proved non-vacuous by putting the bare invocation back into the script: 15 of the 22 tests red**, re-measured on the file as it stands. The 7 that survive are exactly the ones that must pass on both: the upstream exit-0 pin, the well-formed negative control, the real-failure parity case, argument forwarding, and the three controls that only ever invoke the bare tool.

No source, parser, de-identify or public API change. `format` and `format:check` widened to cover `scripts/**/*.mjs`; exactly one pre-existing file entered that glob, `scripts/sync-version.mjs`, verified Prettier-clean before the widening. `lint` was deliberately not widened the same way: the shared ESLint config's rule blocks are scoped to `**/*.ts`, so a seeded unused variable and a missing semicolon in the new script produce zero findings, and widening the glob would add a gate-shaped thing that gates nothing.
