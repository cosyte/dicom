A parsed Element now reads its fields from the parse's compact table, so reading every element of a small file allocates 6 to 14% less, but takes up to 8.2% longer.

- Every field of `Element` is an accessor on the class: `tag`, `vr`, `vm`, `length`, `byteOffset`, `privateCreator`, `cp246Promoted`, `littleEndian`, `specificCharacterSet` and `items`, as `rawBytes` and `value` already were. An Element `parseDicom` built keeps its table, its row, its tag and its VR, and reads every other field from the row when it is asked for; an Element built with `new Element(init)` reads the fields it copied out of `init`. Every field reads the same value as before, and `items`, `rawBytes` and `value` return the same object on every read.
- The cost is time. Measured on GitHub runners against the previous release, base and head in turns on one machine: reading every element of the 50-measurement SR took 4.1 to 8.2% longer and of a CT slice's header 3.9 to 6% longer, and `serializeDicom` took 3.1 to 5.8% longer on the small shapes, because each field read goes through a getter and a table read. Reading every element of the worklist item changed by -0.3 to +1.5%. The same runs found no regression in `parseDicom`. Warm, reading every element allocated 16.8 to 18.3 times the input on the small shapes, down from 19.4 to 20.8.
- An Element has no own enumerable property any more, `_valueCache` included: `Object.keys(el)` is `[]`, a spread `{ ...el }` is `{}`, `JSON.stringify(el)` is `"{}"`, `structuredClone(el)` gives `{}`, and `util.inspect(el)` prints `Element {}`. Assigning to a field, such as `el.tag = x`, which the types already refused, now throws a `TypeError` in strict-mode code instead of changing it. To copy or log an Element, read its fields by name, such as `{ tag: el.tag, vr: el.vr, length: el.length, value: el.value }`.
- Deep-equality helpers see no field either, so `assert.deepStrictEqual`, `assert.deepEqual`, and `toEqual` and `toStrictEqual` in Vitest and Jest pass for any two Elements, even two different ones. A test that compares Elements that way checks nothing. Compare the fields instead, such as `expect({ tag: el.tag, vr: el.vr, value: el.value }).toEqual(expected)`, or compare `el.rawBytes` with `Buffer.equals`.
- An `SQ` Element builds its `Item`s the first time `items` or `value` is read, rather than when the Element is built, and returns the same array of the same Items every time after.
- A parsed Element keeps its parse's table alive, and with it the buffer the table reads: the input, or under `{ copyValues: true }` the one copy of it the parse made. Keeping an Element after its Dataset is dropped keeps that buffer too. To keep only one value, copy it out, such as `Buffer.from(el.rawBytes)` or `el.value`. Each `rawBytes` under `{ copyValues: true }` is still a standalone copy.
- Changes 0.1.13 made and did not name: a parsed `Dataset` or `Item` holds its elements in private fields, so `structuredClone` of one carries no element and `util.inspect` of one shows none; walk them with `elements()`. `_elements` is a getter with no setter, so a subclass that assigns `this._elements` throws a `TypeError`, and one that declares its own `_elements` field no longer changes what `get`, `has`, `elements` and `getAll` return; override those methods instead. `getAll` calls `get`, so a subclass that overrides `get` changes what `getAll` returns too.
